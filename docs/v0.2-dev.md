## v0.2.5 — Drop toolbar icon theme sync + Noto Sans SC bundle

In development; release commit pending. Manifest `0.2.4` → `0.2.5`.

### New Feature

**i18n (中英双语切换).** The UI now ships in English and Simplified Chinese. A two-segment `EN / 中` switcher floats at the bottom-left of the dashboard. On first load, the language follows `chrome.i18n.getUILanguage()` (`zh*` → `zh_CN`, otherwise `en`); once the user picks a language, the choice is persisted under `uiLanguage` in `chrome.storage.local` and wins over the Chrome UI language on subsequent loads.

Implementation is two-track: `_locales/en/messages.json` and `_locales/zh_CN/messages.json` back the manifest `name` / `description` (Chrome's built-in i18n), and a matching `LOCALES` map in `app.js` covers the in-page strings via the `t(key, ...args)` helper. `chrome.i18n.getMessage` is not called at runtime — the in-page path uses `LOCALES` so tests can drive `t()` without mocking the extension's message catalog. `plural('Group', n)` and `timeAgo(value)` route through `t()` so the Reading-list entry timestamps re-localize immediately on switch. `manifest.json` adds `default_locale: "en"`.

**Export / import of the whole group layout.** The `Backup` menu exports a versioned JSON snapshot containing web tabs, custom group names, Reading List entries, and layout/theme preferences. Import validates the schema, merges without reopening duplicate URLs or duplicating Reading List entries, restores missing tabs, and shows a success/error toast. The file picker remains hidden until the user chooses `Import JSON`; Escape or an outside click closes the menu.

Import keeps existing tabs and Reading List entries intact. Chrome's Reading List API does not accept original timestamps, so imported entries receive fresh API timestamps.

### Simplification

- **Drop toolbar icon theme sync.** The `chrome.action.setIcon` light/dark swap (and the offscreen document that fed it) is removed. The new-tab page still follows system `prefers-color-scheme` via its own `matchMedia` listener; only the toolbar icon’s auto-swap is gone. Files deleted: `extension/background.js`, `extension/offscreen.html`, `extension/offscreen.js`. `manifest.json` dropped the `"background"` key and the `"offscreen"` permission. `app.js` lost `notifyTheme()` and its call site; new-tab page theme behavior unchanged.
- **Drop Noto Sans SC CJK fallback.** The 1.1 MB `fonts/noto-sans-sc-regular.woff2` is removed. Terminal font stack now falls back to system `PingFang SC` / `Microsoft YaHei`; the body stack already used these. `style.css` dropped the `@font-face` block. `fonts/CREDITS.md` removed the Noto row + license line and collapsed the "Why no Nerd Font icons" workaround list. Self-hosted fonts went from three files / ~1.23 MB to two / ~123 KB.

Code review:

- **Dark icon variants kept as archive.** `icons/icon-dark.svg`, `icons/icon16-dark.png`, `icons/icon48-dark.png`, `icons/icon128-dark.png` are retained but no longer referenced from any tracked file. They live in `icons/` so a future restoration of toolbar theme sync can be one `setIcon` call away.
- **Influenced blocks:** `manifest.json` (`"background"` key + `"offscreen"` permission dropped; `action.default_icon` keeps only the static light variant); `app.js` (`notifyTheme()` function + call site removed; stale `notifyTheme()`-referencing comment inside the `matchMedia(’change’)` listener updated); `style.css` (`@font-face` block + terminal fallback updated); `fonts/CREDITS.md` (table row, license line, Nerd Font workaround removed; totals updated).

Net: `extension/` ~1.4 MB → 220 KB (-84%).

**Open caveats:**
- The root `README.md` features list still claims `toolbar icons match prefers-color-scheme`; needs to come out at release time.
- `docs/DEVELOPMENT.md` (the relocated dev README) still references `offscreen.*` in the reload hint and `tests/editor.test.js` in validation commands — both stale; follow-up cleanup.


## v0.2.4

New Feature:

**Reading list backed by `chrome.readingList` (Chrome 120+).** The right-column section's data layer moves from `chrome.storage.local` (key `deferred`) to Chrome's Reading List API. Tabulor becomes a view onto Chrome's Reading List: the `readingList` permission is added, the minimum Chrome version is bumped to 120, and live reactivity comes via `chrome.readingList.onEntryAdded/Updated/Removed`. Legacy `deferred` entries migrate on first load — each entry is `addEntry`'d (idempotent by URL), then the local key is removed. No migration flag needed; `addEntry`'s URL-keying makes a re-run a cheap no-op. `dataState.saved` is renamed to `dataState.readingList` and now holds `{url, title, hasBeenRead, creationTime, lastUpdateTime}` (the API entry shape) rather than the legacy `{id, url, title, savedAt, completedAt}`.

**Local mirror for resilience.** A shadow copy of `chrome.readingList` lives in `chrome.storage.local` under `readingListMirror`, written on every successful `query()`. It is the immediate render source on load so the column has data on first paint. On API rejection the mirror stays and `dataState.readingListError` is set so a banner can surface real permission / sync issues. Reactivity for external Reading-list changes (side panel, another extension, another signed-in device) flows through `chrome.readingList.onEntry*` events, not the storage mirror — this avoids the self-write loop that would otherwise come from listening to `storage.onChanged` for our own mirror.

**Unread + Done replace "Reading list" / "Archived".** The right column now renders two peer sub-sections under a centered "Reading list" umbrella header (22px): "Unread" (expanded by default) and "Done" (collapsed by default, renamed from "Pages you've read"). Both are independently collapsible via the `unreadExpanded` / `readExpanded` storage keys, each with its own count badge and chevron. The archive search bar moved out — see [ROADMAP.md](./ROADMAP.md) *Search + keyboard-first*.

**Per-item favicon + paired action button.** Each entry shows a site icon (15×15, 2px radius) at the left slot via the existing `faviconImage` fallback chain (origin `/favicon.ico` → chrome-extension `_favicon/`). The checkbox slot became a paired action button: "mark as read" on Unread (`data-action="complete"` → `updateEntry({hasBeenRead: true})`) and "undo" on Done (`data-action="restore"` → `updateEntry({hasBeenRead: false})`). Both rows now share an identical `.deferred-item` structure — favicon · info · action-btn · dismiss-btn — so the only row-level differences are the icon and the action.





Code review:

**Archive restore icon regression:** `ICONS.undo` was mistakenly classified as unused and replaced by `ICONS.layout`, even though `archiveItemTemplate()` still references it; the archive restore button consequently rendered `undefined`. The original undo SVG has been restored.

**Decisions deferred (recorded, not implemented):**
- **Per-tag pin/star** — out of scope; revisit as an annotation layer over `chrome.readingList` if/when needed.
- **Reading list JSON dump** — deferred to the *Export / import of the whole group layout* backlog item.
- **Cross-browser support** — separate project; the `readingListMirror` is the natural fallback foundation.
- **1px section-line sub-pixel rendering quirk** (`0.994318px` observed in DevTools) — left as-is; would need a defensive `flex-shrink: 0` or a switch to `border-top` to fully pin.

**Dead code removed:** `setDeferred()` function; `.deferred-archive*` / `.archive-*` / `.read-item*` / `.read-action*` / `.deferred-checkbox*` CSS rules; the `deferred` and `archiveOpen` entries in `STORAGE_KEYS`; the `archiveOpen` and `archiveQuery` fields in `uiState`; the inline `#archiveSearch` input handler; `archiveItemTemplate()` function and its `renderArchiveList()` helper.

**Influenced blocks:**
- `STORAGE_KEYS` — `deferred` / `archiveOpen` removed; `readingListMirror` / `unreadExpanded` / `readExpanded` added.
- `dataState` — `saved` renamed to `readingList`; `readingListError` flag added.
- `uiState` — `archiveOpen` / `archiveQuery` removed; `readExpanded` / `unreadExpanded` added.
- `loadState()` — one-time migration block (read legacy `deferred`, `addEntry` each, `remove('deferred')`); reads `readingListMirror` as the immediate render source.
- `refresh()` — calls `refreshReadingList()` after `render()`, then `registerReadingListListeners()` (registered once per page load).
- `refreshReadingList()` (new) — queries API, normalises to the legacy-shaped mirror, writes mirror, re-renders; on rejection keeps the mirror and sets `readingListError`.
- `registerReadingListListeners()` (new) — subscribes to `chrome.readingList.onEntryAdded/Updated/Removed`; idempotent via a module-level flag.
- `savedItemTemplate` / `readItemTemplate` — structurally identical; only the icon and the action differ.
- `savedActions` — `complete` / `dismiss` / `restore` call `chrome.readingList.updateEntry` / `removeEntry` then `refreshReadingList()`.
- `tabActions.save` — calls `chrome.readingList.addEntry` then closes the tab.
- `chrome.storage.onChanged` listener — dropped the `deferred` branch (mirror writes don't loop; reactivity flows through `chrome.readingList` events instead).

**Test coverage:** `tests/editor.test.js` case 9 exercises the legacy `deferred` migration path (three entries, including one `dismissed` and one with `completedAt`) and asserts: dismissed entries are skipped, `completedAt` maps to `hasBeenRead: true`, the legacy key is removed from storage, and `dataState.readingList` is populated from the fresh API snapshot. `tests/helpers/chrome-stub.js` ships a functional `chrome.readingList` stub (URL-keyed uniqueness, fires `onEntry*` events).

**Open caveats:**
- `chrome.readingList` is Chrome-only — Firefox / Safari fall through to an empty Reading list (the chrome-extension `_favicon/` permission is the only related gate today).
- Chrome's Reading List syncs across signed-in Chrome instances via profile sync — this is the platform's behavior, not Tabulor's; users coming from `v0.2.x` may notice their saved tabs appearing on other devices.
- `dataState.readingListError` is set on API rejection but the banner UI for it isn't rendered yet — planned as a follow-up if transient failures become common.






Bug Fix:

**Section-count header alignment (commit `d8b016c`).** Open-tabs column now self-scrolls (its scrollbar hidden; the right column keeps its scrollbar for the save/archive affordance). The `13 domains · Close all N tabs` row is now on a coherent optical baseline: dot font `11 → 12px` and lifts `-1px` via `transform: translateY(-1px)` (with `display: inline-block` so the transform actually applies; the earlier `translateY(-2px)` was being silently ignored on the inline span), dot's right margin `8 → 9` to absorb the tighter button. Close button's left pad `8 → 6`; right pad stays `8` for label breath. Container padding-bottom `72 → 32` to fit the new chrome height. The unfinished items from the original WIP `ce66bc6` are now closed (the dot's vertical alignment, the section-line / section-count optical alignment). The original WIP is folded into `d8b016c` via `--amend`, so this entry covers the whole self-scroll + alignment thread.



## v0.2.3 — Reading list rename + stable group ordering

New Feature:

- **Switch Open tabs between single- and multi-column.** Header icon toggle (multi-column grid icon over a grid-list icon) flips the `Open tabs` region between multi and single column; preference persists alongside other layout settings. Default is multi.
- **Reading list rename.** Right-column section relabeled from "Bookmark" to "Reading list" to match its semantic shape (local, flat, ephemeral, manual archive) and to clear the way for the planned `chrome.readingList` migration. See [ROADMAP.md](./ROADMAP.md) → *Migrate saved section to `chrome.readingList` (core direction)*.

Fix:

- **Fix tag-delete group jumping.** Group ordering now follows the first tab's position in the live tab list rather than changing with tab counts, keeping the current group stable during consecutive removals.

Code review (this round):
- **Dead code removed:** duplicate `.mission-card { margin: 0; }` was removed and the temporary `layoutButton` constant was inlined into `render()`.
- **Influenced blocks:** click delegation via `uiActions` (new `toggle-layout`), `render()` template (icon button + conditional `layout-single` class), `loadState()` (new `openTabsLayout` storage key, defaults to `multi`), `STORAGE_KEYS` map, `LAYOUTS` whitelist, `applyTheme()` unaffected, storage `onChanged` listener unchanged (layout toggles stay inline like `styleId`).
- **Open caveats:** icon `aria-label` hardcodes English target state; no smoke test added for `toggle-layout`; layout class swap is CSS-only and does not require a full refresh.

Full release notes: see the `release: v0.2.4` commit when it is tagged.

## v0.2.2 — Archive redesign + terminal scrollbar

Release commit [`36264e4`](https://github.com/CaiShawn/tabulor/commit/36264e4). Manifest `0.2.1` → `0.2.2`.

- **Archive module redesign.** Saved section renamed to "Bookmark"; archive section renamed to "Archived". Collapsed archive is a foldable section-header with open/closed persisted via `archiveOpen`; per-item restore + dismiss actions.
- **Search.** Archive filter now accepts a single character (2-char minimum dropped).
- **Terminal scrollbar.** Saved-column scrollbar themed via WebKit/Blink + standard `scrollbar-width`/`scrollbar-color`; scoped to `[data-style="terminal"]` only.
- **Token cleanup.** Archive borders moved off hard-coded Classic-only colors onto the `--line` token; archive action buttons reuse `.chip-action`.

Dev-branch-only docs reorganized in the same window (ROADMAP status board, AGENTS template, v0.1 flaw review); these land on `main` as separate doc-only commits.

## v0.2.1 — First SemVer release

Release commit [`ba7b9e16`](https://github.com/CaiShawn/tabulor/commit/ba7b9e16). Manifest `2.0.0` → `0.2.1` (pre-1.0 SemVer).

- **Selectable visual styles.** Classic (rounded) and Terminal (sharp + monospace), `styleId` persisted; light/dark and style remain independent dimensions.
- **Self-hosted font bundle.** Inter, Meslo LG Mono, Noto Sans SC served from `extension/fonts/`; no external font request.
- **Terminal-style icons.** Light + dark PNG/SVG variants; manifest updated.
- **Toolbar icon follows OS color scheme.** `chrome.action.setIcon` swaps on theme-change; offscreen document watches `prefers-color-scheme` because MV3 service workers cannot use `matchMedia`.
- **Domain-only grouping.** The fork's `landingRules` table (163/QQ Mail, Bilibili, Weibo, Xiaohongshu, Zhihu as "Homepages") removed; all tabs group by hostname alone, with same-label auto-merge.

> A theme-neutral single icon for the tab bar was proposed and rejected by the user ("效果不好，不用继续了"); the toolbar / puzzle-menu is the only spot that can follow the theme.
