> The full development record for Tabulor v0.1: architecture snapshot, product surface inherited from the upstream fork, and the defect / product-fit review against that baseline. Read this file when working on the v0.1 baseline or before v0.2 lands.

## Architecture

> **Frozen snapshot.** This section is the architecture as of v0.1 and is **not edited in place**. When the architecture changes in a later version, update `v0.2-dev.md` (or a newer `v{N}-dev.md`) and let this section stand as historical.

Developer-facing notes for Tabulor's internals at v0.1. Lives outside the user-facing `README.md` so the two can evolve independently — the README is for users and installers, this document is for contributors.

### State and storage

`extension/app.js` reads and writes local state through `chrome.storage.local`.

Important keys include:

| Key | Purpose |
|---|---|
| `deferred` | Saved tabs and their completion/archive state |
| `theme` | Explicit light/dark value when present |
| `styleId` | Active visual style: `classic` or `terminal` |
| `customGroupNames` | User-defined labels keyed by group identifier |

Storage schema changes should be treated as compatibility-sensitive even while the extension is unreleased.

### Grouping

Web tabs are grouped by hostname unless a custom local rule assigns another group key. Groups sharing the same display label are merged into one card. Representative selection favors:

1. a group with a custom name;
2. the local-files group;
3. the group with more tabs;
4. a deterministic lexicographic fallback.

### Styling

`extension/style.css` contains both visual systems:

- `data-style="classic"` uses the original rounded dashboard presentation.
- `data-style="terminal"` overrides color and radius tokens for the terminal presentation.
- `data-theme="light|dark"` controls the active palette.
- The `.terminal` body class applies the terminal font stack.

Style and light/dark theme are separate state dimensions. New styles should preserve this separation rather than introduce a combined style-theme identifier.

### Fonts

Fonts are served from `extension/fonts/`; the extension makes no external font request. Attribution and source information belong in `extension/fonts/CREDITS.md`.

### User-defined grouping rules

`extension/index.html` loads an optional `config.local.js` before `app.js`. The file is gitignored and is the supported extension point for personal grouping rules. When present, it should expose a global `LOCAL_CUSTOM_GROUPS` array of objects shaped like:

```js
[ { hostname: 'mail.google.com', groupKey: 'mail', groupLabel: 'Mail' }, { hostnameEndsWith: '.feishu.cn', groupKey: 'feishu', groupLabel: 'Feishu' }, { hostname: 'github.com', pathPrefix: '/issues', groupKey: 'gh-issues', groupLabel: 'GitHub Issues' },
]
```

A missing file is harmless; the dashboard falls back to host-based grouping.

## Core Function (from tab-out)

> Product behavior inherited from the original tab-out fork; ships on both `main` and `dev`.

These were already present in the initial fork commit and ship on both `main` and `dev`. Listed here only so future readers know which product behaviors are *floor* behavior, not dev-only work:

- Domain-based grouping (with `local-files` bucket for `file:` URLs)
- Saved-for-later (`deferred`) with completion → archive flow
- Archive list with title/URL search and 2-char minimum query
- Duplicate tab detection + dedupe action
- 8+ tabs overflow (`+N more`) per group
- Inline group rename via pencil icon, persisted via `customGroupNames`
- Same-label auto-merge across groups
- Light/dark theme that follows `prefers-color-scheme`
- One-click close-all and close-group
- Custom hostname rules via `config.local.js` → `LOCAL_CUSTOM_GROUPS`

## Already removed from v0.1 (do not re-introduce)

These were inherited from upstream and consciously dropped during the fork. Documented here so future readers know they were deliberate, not oversights.

- **Close sound effect** (`playCloseSound` / Web Audio API noise sweep).
- **Confetti particle burst** (`shootConfetti` / DOM particles).
- **Closing card animation** (`animateCardOut` / `closing` class with confetti trigger).
- **Tab-Out dupe banner** (`#tabOutDupeBanner` / `closeTabOutDupes`).
- **Update banner** (sage-green "new version available" strip).
- **Mission-card status tags** (`.mission-tag.active | .cooling | .abandoned` and the three-state color coding).
- **`Homepages` special-case group** (`LANDING_PAGE_PATTERNS` / `__landing-pages__` / `closeTabsExact` path).
- **Greeting + date in the header** (`Good morning` / `Friday, April 4…`).
- **External Google Fonts request** (Newsreader + DM Sans). Replaced by the self-hosted Inter / Meslo LG Mono / Noto Sans SC bundle.
- **Footer stats + "Tab Out by Zara" credit line.**
- **`Localhost` port-prefix labelling** in chip titles.
- **`getRealTabs()` filter for chrome:// / chrome-extension:// / edge:// / brave://** is kept in spirit but simplified in `isWebTab()`.

## Flaw review

A side-by-side review of Tabulor v0.1 (forked from [tab-out](https://github.com/zarazhangrui/tab-out)) against the upstream codebase, listing every place where v0.1 still does not match Tabulor's product direction or has internal smell.

Intended use:

- Each entry below is a candidate for the next version.
- When a version (v0.2, v0.3, …) closes one or more items, link the closing commit/PR next to the entry. Keep this section as the historical defect list — do not delete closed items.

The review was conducted on the `dev` branch at `0.2.1`.

### A — Architecture / data model

#### A1. Tab list is still the source of truth (open)

`dataState.tabs = await chrome.tabs.query(...)` is the model. Groups are recomputed on every render via `buildGroups()` + `mergeByLabel()`.

Consequence: dedupe, save, close-group all do "re-derive group → look up tab id → call chrome.tabs.remove → refresh again". If `chrome.tabs` state changes between the snapshot and the action, the dashboard can show "3 tabs left" while Chrome has 1.

**Resolution path:** ROADMAP "Group as the core data structure" already names this. Move group identity into the persisted state and treat the tab list as an input feed.

#### A2. Rendering is full-rebuild, not patch (open)

Any state change (close tab, rename group, theme switch, archive toggle) calls `render()` which rewrites the entire `#app` `innerHTML`. Terminal style + 60+ chips = a visible flash.

**Resolution path:** same as A1 — Group-as-source-of-truth also unlocks incremental DOM patches. Until then, the `no-anim` container class and the `firstRender` flag partially hide it.

#### A3. `lastGroups` is a redundant module-level mutable (open)

`render()` writes `lastGroups = groups`, then actions like `close-group` and `dedupe` read back via `groupAt(index)`. The same group information exists in `lastGroups` and will be re-derived next `refresh()` from `dataState.tabs`.

If an action runs during an in-flight `refresh()`, it can read stale group info. `refreshInFlight` coalescing makes the race unlikely but not impossible.

**Resolution path:** A1.

#### A4. Editor keys use a string lookup across `dataState` and `lastGroups` (open)

`uiState.editingKey` stores `group.key`. `commitEditor()` then does `lastGroups.find(g => g.sources.some(s => s.key === key))`. The lookup chain spans the data state, the render snapshot, and the merged group's source list.

When v0.2 introduces `Group-as-source-of-truth` and `sources` may go away, this lookup breaks silently.

**Resolution path:** A1; expose a `groupByKey(key)` that talks to a single store.

### B — UX / product

#### B1. `chip-save` uses the literal character `☆` (low)

All other actions use inline SVG icons (`close`, `tabs`, `edit`, `iconSun`, `iconMoon`). The star is the only escapee. Trivial fix: swap to an SVG bookmark icon.

#### B2. "Close all N tabs" sits in the section header (low)

It works, but in Terminal style the amber-bordered button next to the section count is louder than the rest of the dashboard. Visual calm is one of Tabulor's stated goals.

**Resolution path:** either move it into an overflow menu or tone the button down.

#### B3. `focusout` × `data-action` click race (medium)

When the editor is open and the user clicks a chip's close button:

1. `click` handler runs, sets `el.disabled = true`, calls `closeWithEffect` → `refresh()`.
2. `focusout` fires on the input, calls `commitEditor()`.

Both run concurrently and both eventually `await refresh()`. The result is unpredictable depending on order.

**Resolution path:** either disable the editor commit on focusout (rely on Enter / Escape / explicit cancel) or cancel the editor before dispatching any action.

#### B4. No user-facing theme switcher (intentional)

Upstream also has none. Confirmed intentional: theme follows the OS via `prefers-color-scheme`; the only override is an explicit `theme` key in storage. Keep as-is.

### C — Engineering

#### C1. `_diag` ring buffer in production `background.js` (medium)

`diag()` writes every theme/badge decision to `chrome.storage.local['_diag']` as an 80-line ring buffer. This was a debugging aid for the toolbar icon work and should not ship to release builds.

**Resolution path:** gate behind a build flag, or remove before 0.2.x ships.

#### C2. `LOCAL_CUSTOM_GROUPS` schema is a subset of upstream (low)

Upstream supported `test(pathname, url)` (full predicate) plus `hostnameEndsWith`. v0.1 supports `hostname`, `hostnameEndsWith`, `pathPrefix`, `pathExact`. Missing: the `test` callback. Any user carrying over an upstream `config.local.js` will silently lose predicates.

**Resolution path:** either re-add `test` support or call out the gap in the docs explicitly.

#### C3. Favicon fallback fires every dashboard open (low)

Each tab's chip tries `tab.favIconUrl` → `origin/favicon.ico` → `chrome://_favicon/?pageUrl=...&size=16`. The `error` event handler swaps to the next candidate. Net effect: on first paint every broken favicon triggers a swap, costing 1–2 frames per broken favicon.

**Resolution path:** cache successful favicon URL per-tab in `dataState` or use `<link rel="prefetch">` during idle.

#### C4. Test coverage is grouping-only (medium)

`tests/editor.test.js` covers `buildGroups()` + `mergeByLabel()`. The archive flow, dedupe action, save action, and rename commit logic have no tests. Upstream had no tests at all — Tabulor is the first to add any, but the most-touched product flows remain uncovered.

**Resolution path:** before Group-as-source-of-truth (A1) lands, add tests for: deferred state transitions (save → active → complete → archive → dismiss), rename commit, and the refresh coalescing in `refresh()`.

#### C5. `_diag` storage key is not in `STORAGE_KEYS` (low)

`background.js` writes `chrome.storage.local._diag`, but neither `app.js` nor `background.js` declares the key in their respective `STORAGE_KEYS`. Safe today because no code reacts to changes on that key, but a future `storage.onChanged` listener that filters by "known keys" will either drop it (good) or trigger an extra refresh (bad) depending on how the filter is written.

**Resolution path:** when C1 is resolved (remove `_diag` from production), this becomes moot.

### D — Resolved during v0.1 (historical, for context)

- ✅ **Selection of two visual styles** (Classic + Terminal) via `data-style` / `data-theme` separation.
- ✅ **Self-hosted font bundle** (Inter / Meslo LG Mono / Noto Sans SC).
- ✅ **System-aware light/dark palettes** independent of style choice.
- ✅ **Toolbar icon follows `prefers-color-scheme`** via the offscreen document.
- ✅ **Domain-only grouping** (dropped the homepages special case).
- ✅ **Inline group rename** with persistence via `customGroupNames`.
- ✅ **Same-label auto-merge** for cross-domain groups.
- ✅ **SemVer 0.2.x** in `manifest.json`.
- ✅ **Manual code reduction** across `app.js` / `style.css` / `index.html` versus upstream.
